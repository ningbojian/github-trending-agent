# ADR 0009：跟踪只报「值得看的变化」，不做第二个 GitHub Watch

**状态**：已采纳（2026-10-29）

## 背景

用户希望把「单向榜单」变成「可订阅自己关心的仓库」：丢一个 GitHub 链接给机器人，仓库更新时通知。GitHub 原生 Watch 已覆盖「有新事件就通知」，直接照搬只会是重复造轮子——而且是更差的那个：Watch 是英文事件流水，issue/PR/star 变化都推，不排序、不解释、不跨源。

真正空着的位置是：**只告诉你值得看的那一小部分变化，并用中文解释它是怎么回事**，而且能和每日简报共存、不互相打扰。

## 决策

- 新增 `tracked_items`（migration 0005）：`(wecom_userid, source, kind, identifier)` 唯一，`identifier` 规范化（仓库小写 `owner/repo`），`cursor` 存上次检查位置（release tag、上次 star、归档状态）。每用户最多 10 个 active。
- 命令：`追踪 owner/repo`（或 GitHub 链接）、`我的追踪`、`取消追踪 N|owner/repo`。第一次追踪用**当前** release/star 建基线，不把已有 release 当新闻。
- 每日检查（`pushTrackedChanges`，跑在 cron 里）：
  - 只查 20 小时未检查、且订阅者仍 active 的项；
  - 按用户原子处理：剩余预算不够覆盖这个人的全部条目就整人跳过，绝不「查一半就标记」；
  - 变化判定由代码完成：新 **stable** release（tag 变化且发布时间更新）、star 加速（`≥ max(50, 当前 5%)`）、仓库归档；
  - 每人每天最多一条「跟踪变化」摘要（marker 48h，发送前写，at-most-once）；
  - **cursor 只在发送成功后推进**；发送失败保留旧 cursor，下个 tick 重试；
  - 不写 `push-history`：跟踪提醒与简报去重是两件事，混在一起会把仓库从简报里静默移除。
- 没有 `GITHUB_TOKEN` 时不检查（未认证 60 次/小时撑不起批量检查），命令仍可用。
- 作者跟踪、HF/模型、arXiv 论文放到后续阶段；表里的 `source` / `kind` 已预留。

## 后果

- 跟踪是「安静」的：没有实质变化的日子不会发消息；这符合「只报值得看的」定位。
- 不是实时通知：受调度限制，最迟在下一个 tick 才发出；产品文案不承诺秒级。
- 每人最多一条/天、最多 10 个跟踪项，避免变成新的信息噪音。
- 隐私：`tracked_items` 把用户与仓库关联，绝不进入聚合指标/共享缓存；退订时不自动删除（用户可能仍想跟踪），但订阅者 `active=false` 时检查会跳过。
- 迁移纪律照旧：`when` 必须大于上一条；本次为 `1793205725786`，账本 6 条，表已核对。
