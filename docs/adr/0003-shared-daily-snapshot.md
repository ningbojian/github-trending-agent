# ADR 0003：当日快照只构建一次，两个渠道共用

**状态**：已采纳

## 背景

同一批热榜要发给企微成员与邮箱订阅者。若每个用户各调一次模型生成中文简介，成本随用户数线性增长；而 top10 的内容与用户无关，个性化只体现在「挑哪几行」。

## 决策

- 每小时 tick 读取一份**当日快照**（`getDailySnapshot`）：候选查询每次重跑，用数据日期判断缓存是否过期；**不抓取、不补全**（那两步在 `daily.yml` 里），只做一轮模型生成仓库简介 + 一次 Abstract。缓存键 `digest-snapshot:<日期>`，TTL 24h。
- 两个渠道读同一份快照。企微侧个性化在内存里做——按语言/关键词过滤、按收藏与反馈加权排序、按渠道截断（1900 字节，上游上限 2048）；邮箱侧只做语言/关键词过滤与条数截断，不读收藏与反馈信号，也不排除已 star 的仓库。
- 数据库里的 `favorites` **参与**语言加权（同一语言 ≥2 条才计入，避免单次收藏带偏）；只有推送时从 GitHub 拉到的网页端 star 不参与加权，只并入「不推」集合，避免同一批收藏被算两遍。
- 快照构建失败返回 `null`：企微逐订阅者回退到「查库 + 模板」，列表仍然送达；邮箱这一轮直接跳过（不发半份简报），等下一轮 tick。

## 后果

- 模型调用从 O(用户数) 降到 O(1)/小时；新增用户几乎不增加 LLM 成本。
- 个性化上限受快照内容限制：快照里没有的仓库不可能被推给任何人。
- 快照是一天的口径，用户偏好变化要等下一份快照才完全生效（排序仍实时）。
